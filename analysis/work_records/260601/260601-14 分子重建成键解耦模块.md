# 260601-14 分子重建成键解耦模块

## 一、动机/背景

当前 DiffSBDD 的基础模型只生成 atom cloud，生成后的键由重建/成键算法补出来。前面重建消融显示：OpenBabel 在真实坐标上边选择几乎不差，但 bond order、芳香性、sanitize/valence 仍会显著影响最终有效性；因此下一步不应先把完整 edge diffusion 硬塞进主模型，而应先把“分子重建/成键”从生成流程里抽成可切换模块。

这一步的目标不是立即提升质量，而是先建立可控接口：默认行为完全保持 OpenBabel，不影响已有训练和生成；同时给 EDM distance-rule 留出开关，后续可以把成熟 bond predictor 或完整 bond diffusion decoder 接到同一个入口。

| 方法 | sanitize | edge F1 | bond type acc |
|------|----------|---------|---------------|

## 五、结果与意义

本次完成的是“接口与主线解耦”，不是最终化学质量优化。现在 OpenBabel 不再硬编码在生成和 RL 语义流程里，而是变成一个默认 backend；后续可以在同一层接入：

1. supervised bond predictor；
2. DiffGui/DecompDiff 风格的 explicit bond reconstruction；
3. 完整 edge diffusion decoder；
4. sampling-time geometry guidance 后的 reconstruction 对照。

这让后续实验可以用同一批 generated atom cloud 对比不同成键器，避免把“基础模型生成差”和“后处理成键差”混在一起。

## 六、剩余风险

| 风险 | 说明 | 后续处理 |
|------|------|----------|
| 字段名仍有 OpenBabel 历史痕迹 | `obabel_reconstruct_success`、`openbabel_reconstruct_failed` 为兼容旧 CSV/奖励链暂未重命名 | 后续单独做 schema 迁移，不和本次解耦混改 |
| EDM method 只是已有距离规则 | 它不是更强方法，只是可切换对照 | 下一步训练/接入成熟 bond predictor |
| docking fallback 局部仍默认 OpenBabel | 正常主链复用 `annotate_batch_molecule_semantics()` 的 `rdmols`；只有缺失时 fallback | 后续如要全链路严格可配，再给 docking preparation 增加 reconstruction config |
| 质量未做新生成大样本评估 | 本次只验证接口和训练主链不崩 | 下一步做 OpenBabel vs EDM vs bond predictor 的同源 atom cloud 对照 |

## 七、下一步建议

先用同一批 DiffSBDD atom cloud 做 reconstruction ablation：

1. `openbabel` baseline；
2. `edm` distance-rule；
3. 新增 supervised bond predictor；
4. 用统一评价脚本比较 validity、sanitize、fragment、bad bond length、ring/aromatic、docking input success 和速度。

这个实验能回答“只换成键器能救多少”，再决定是否投入完整 edge diffusion。
