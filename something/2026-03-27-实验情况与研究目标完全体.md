# 基于深度强化学习的蛋白质靶向分子生成系统——实验情况与研究目标

**核心靶点**：RE-CmeB（鲍曼不动杆菌多药外排泵蛋白，PDB: 8GJJ）

## 3.1 研究背景与科学问题

### 3.1.1 靶点背景与临床意义

RE-CmeB是多重耐药病原体鲍曼不动杆菌（*Acinetobacter baumannii*）中CmeABC外排泵系统的核心膜蛋白组分，归属于抵抗-结节-细胞分裂（RND）超家族。该蛋白以三聚体通道形式存在，借助质子动力势将β-内酰胺类、氟喹诺酮类等多种抗生素主动泵出胞外，是鲍曼不动杆菌产生广泛耐药性的核心机制之一。其晶体结构已部分解析，呈现出典型的跨膜螺旋束与胞外环结构，为基于结构的药物设计提供了明确靶点。值得注意的是，RND家族同源蛋白（如大肠杆菌AcrB）已有约50个已知抑制剂，且表现出一定广谱性；然而RE-CmeB本身抑制剂稀少，这既为本研究带来了挑战，也为发现全新骨架的外排泵抑制剂提供了广阔空间。针对RE-CmeB开发新型外排泵抑制剂，旨在阻断抗生素外排通路、协同恢复现有药物疗效，是应对全球抗生素耐药危机的极具前景的策略。

### 3.1.2 现有计算方法的局限

传统基于结构的药物设计（SBDD）依赖高通量虚拟筛选或遗传算法优化，难以同时兼顾分子结合性、类药性与结构新颖性，且对缺乏活性数据的靶点（如RE-CmeB）适用性有限。近年来，深度生成模型在从头分子设计领域取得重要进展，其中以DiffSBDD为代表的条件扩散模型能够以蛋白质口袋结构为条件，直接在三维空间中生成新颖配体的原子坐标与类型，具有显著的结构感知优势。然而，纯粹的生成模型在无监督训练阶段缺乏针对特定靶点的优化导向，所生成分子在对接亲和力、合成可达性及类药性等关键指标上表现参差，难以直接转化为候选药物。

## 3.2 核心技术框架

### 3.2.1 扩散模型基础：DiffSBDD

DiffSBDD是一种SE(3)-等变的三维条件扩散模型，将蛋白质口袋和配体均表示为三维点云图，通过去噪扩散概率模型（DDPM）学习真实配体结合构象的分布。在前向过程中，模型对配体坐标和原子类型逐步加噪：

$$\mathbf{x}_t = \sqrt{\alpha_t}\,\mathbf{x}_0 + \sqrt{1-\alpha_t}\,\boldsymbol{\epsilon}, \quad \boldsymbol{\epsilon}\sim\mathcal{N}(0,I)$$

在反向去噪过程中，以蛋白质口袋结构为条件，从纯噪声出发逐步恢复配体结构，同时生成原子坐标 $\mathbf{x}$ 与原子类型特征 $\mathbf{h}$（离散类别编码）。DiffSBDD的关键特性是保持平移、旋转和排列对称性（SE(3)-等变），但对反射敏感，从而能区分影响活性的不同立体化学构型。其已验证的功能包括从头配体生成、基于已知子结构的局部分子设计（骨架跃迁、片段连接）以及迭代分子优化，是本研究生成骨架的核心引擎。

### 3.2.2 强化学习框架：RLPF与DDPO

RLPF（Reinforcement Learning for Physical Feasibility）是一种用于强化学习等变扩散模型的框架，其核心思路是将扩散去噪过程建模为马尔可夫决策过程（MDP），以多维奖励函数的反馈引导模型迭代优化分子生成策略。本研究在此框架基础上实现了DDPO（Denoising Diffusion Policy Optimization）训练，采用近端策略优化（PPO）算法更新模型参数。

**策略比率（重要性采样）**：

$$r_t = \frac{\pi_{\theta_{\text{new}}}(\mathbf{x}_t|\mathbf{x}_{t+1})}{\pi_{\theta_{\text{old}}}(\mathbf{x}_t|\mathbf{x}_{t+1})} = \exp\!\left(\log p_t^{\text{new}} - \log p_t^{\text{old}}\right)$$

**PPO-Clip 目标函数**：

$$L_{\text{PPO}} = -\mathbb{E}\left[\min\!\left(r_t\hat{A}_t,\;\text{clip}(r_t, 1-\epsilon, 1+\epsilon)\hat{A}_t\right)\right]$$

其中裁剪参数 $\epsilon$ 极小（量级约 $10^{-4}$），以防止扩散模型在PPO迭代中发生分布崩溃。优势函数当前直接取奖励信号，后续计划引入基线减法与归一化以提升训练稳定性。

整个训练框架基于 **PyTorch Lightning** 实现，通过 DDP（分布式数据并行）策略支持多GPU同步训练，当前主要运行于 4–8 张 NVIDIA RTX 3080（各10GB显存）的服务器环境中。

## 3.3 分子生成流水线与语义规范

### 3.3.1 规范化分子重建流程

为确保奖励计算、类药性评估与对接准备共享同一分子对象、避免多路径语义分歧，本研究制定了如下规范化流水线：

1. 扩散模型生成原始样本 $(\mathbf{x}, \mathbf{h}_{\text{categorical}}, \text{nodesxsample})$
2. 依据 `nodesxsample` 去除 padding，提取有效原子坐标与类型
3. 使用 **OpenBabel** 从扩散几何结构重建化学键，感知拓扑结构
4. 将重建结构转换为统一的 **RDKit `Mol`** 对象（`rdmol`）
5. 对 `rdmol` 执行 RDKit sanitize / 合法性检查（`rdkit_valid`）
6. 以该 `rdmol` 直接计算 QED / SA，不经 SMILES 中转
7. 由该 `rdmol` 导出 SDF / PDBQT 作为对接输入
8. SMILES 仅用于日志记录、CSV导出与新颖性去重

这一单一来源原则（Rule A）确保了过滤模块、类药性奖励与对接奖励之间的语义一致性，同时明确了失败类型的边界：OpenBabel重建失败（`build_failed`）与RDKit合法性失败（`sanitize_failed`）分属两个独立的失败门，失败样本获得最大惩罚奖励并跳过所有后续计算阶段。

### 3.3.2 每分子追踪字段体系

每个生成样本在流水线中按如下分层字段进行追踪：

| 层次 | 关键字段 |
|---|---|
| 样本层 | `x`, `categorical`, `nodesxsample`, `sample_id` |
| 重建层 | `obabel_reconstruct_success`, `rdmol`, `build_success` |
| RDKit合法性层 | `sanitize_success`, `rdkit_valid` |
| 表示层 | `smiles`, `canonical_smiles` |
| 类药性层 | `qed`, `sa_raw`, `sa_norm`, `druglikeness_reward`, `druglikeness_success` |
| 对接层 | `docking_input_success`, `dock_success`, `dock_score_raw`, `dock_score_norm`, `docking_reward` |
| 最终奖励层 | `total_reward`, `failure_type` |

## 3.4 多维奖励函数设计

### 3.4.1 总体框架

奖励体系采用分层设计：各组件奖励保持独立可见，权重统一存放于YAML配置文件，通过 `CompositeReward` 加权求和后由 `StabilityAwareReward` 包装输出最终奖励。整体计算流程如下：

```
生成样本
  ↓
[OpenBabel重建] → 失败 → failure_type=build_failed, reward=-1.0
  ↓ 成功
[RDKit sanitize] → 失败 → failure_type=sanitize_failed, reward=-1.0
  ↓ 成功 (rdkit_valid=True)
[类药性奖励] QED + SA
  ↓
[对接奖励] AutoDock-GPU → ΔG → 归一化
  ↓
[CompositeReward] 加权求和
  ↓
最终 total_reward
```

### 3.4.2 类药性奖励（DruglikenessReward）

类药性奖励综合考量定量药物相似性（QED）与合成可达性（SA Score）两个核心指标：

$$R_{\text{drug}} = w_{\text{QED}} \cdot \text{QED} + w_{\text{SA}} \cdot \frac{10 - \text{SA}}{9}$$

其中 QED $\in [0,1]$，SA Score $\in [1,10]$（1表示易于合成），通过线性归一化映射为 $[0,1]$ 区间。当前配置中两者权重均为0.5，权重值存储于YAML配置文件，实验中可灵活调整。无效分子（`rdkit_valid=False`）不进入本模块计算，直接获得惩罚奖励。

### 3.4.3 对接奖励（DockingReward）

对接奖励以AutoDock-GPU为计算后端，以蛋白质口袋 `data/8GJJ-C-Cip_charged.maps.fld` 为受体格点，对每个RDKit合法分子进行GPU加速分子对接，获取估算结合自由能 $\Delta G$（kcal/mol），并按归一化因子映射为奖励：

$$R_{\text{dock}} = \frac{\Delta G}{\Delta G_{\text{norm}}}$$

参考值取 $\Delta G_{\text{norm}} = -10.0$ kcal/mol（参照文献报道的强结合配体区间），使得 $\Delta G = -10$ kcal/mol 时 $R_{\text{dock}} = 1.0$。对接失败样本（OpenBabel/RDKit流程中已被门控过滤）不参与对接计算，记录为 `dock_success=False`，贡献零对接奖励并计入失败统计。

AutoDock-GPU的设备编号采用1-indexed方式（`--devnum`），与CUDA的0-indexed方式存在偏移（代码中以 `devnum = gpu_id + 1` 显式换算），已通过参考配体 `cip.pdbqt` 的烟雾测试验证：参考配体对接结果为 $-4.91$ kcal/mol（估算结合自由能），与晶体结构吻合，证明对接管道工作正常。

### 3.4.4 复合奖励（CompositeReward）

最终奖励为各组件的归一化加权和：

$$R_{\text{total}} = \sum_i w_i \cdot R_i, \quad \sum_i w_i = 1$$

当前实验阶段主要运行 **druglikeness-only** 配置（$w_{\text{drug}}=1.0$，对接组件暂时关闭），以验证强化学习闭环的正确性后再逐步引入对接奖励。完整多目标配置计划为：

| 组件 | 权重（计划值） | 说明 |
|---|---|---|
| `druglikeness` | 0.25 | QED + SA，评估类药性 |
| `docking` | 0.5 | AutoDock-GPU，评估结合亲和力 |
| `interaction` | 0.25 | ProLIF残基相互作用奖励（计划中）|

### 3.4.5 计划中的高级奖励组件

**ProLIF残基相互作用奖励**：本课题组前期分子动力学模拟已对RE-CmeB活性口袋的41个组成残基（参照AcrB同源蛋白，按空间分布划分为近端和远端口袋）进行了多维动态特征分析，获取了各残基对底物结合响应的重要性评分。计划利用ProLIF库量化生成分子与这些关键残基之间的相互作用类型（氢键、疏水接触、π-π堆叠等），并以残基重要性评分为权重，构建残基级别的相互作用奖励，引导模型优先生成与关键口袋残基形成高质量相互作用的分子。

**MolFormer流形判别器**：针对强化学习无限追求打分可能导致生成高分但化学上不合理分子的问题，计划训练一个基于MolFormer分子语言模型嵌入的流形判别器。MolFormer在约11亿个无标注分子（PubChem + ZINC）上进行掩码语言模型预训练，采用Transformer编码器结合线性注意力与旋转位置编码，将SMILES转换为768维化学语义嵌入。具体实现为：在DrugBank、ChEMBL等药物数据库的分子SMILES上提取MolFormer嵌入，通过UMAP降维（768→32维，余弦距离度量）构建低维药物流形，并使用KDTree建立近邻索引。在训练过程中，对生成分子的SMILES提取MolFormer嵌入并投影到同一流形空间，计算其与已知药物分布的距离；判别器能够区分出"不在药物流形内"的分子时给予惩罚，仅当生成分子通过流形判别后，才进入后续对接等计算奖励阶段。需要特别指出的是，本方案刻意不使用3D分子指纹，原因在于大型数据库中分子的3D构象为能量最低态构象，并非针对特定靶点的结合构象，与本研究扩散模型生成的靶点口袋结合构象存在本质差异；因此将生成分子转化为1D SMILES后提取二维拓扑指纹，再在药物流形空间进行合理性判定，是更为合理的技术路线。

## 3.5 当前实验进展

### 3.5.1 系统集成与端到端验证

本研究已完成DiffSBDD扩散模型与RLPF强化学习框架的完整集成，实现从分子采样、语义标注、奖励计算到PPO更新的全闭环训练流程。具体里程碑包括：

技术栈：

- RL框架：RLPF-verl_diffusion（`EDMActor` + `EDMRollout`）

- 对接后端：AutoDock-GPU（`/usr/local/bin/autodock_gpu_64wi`），1-indexed `--devnum`
- 受体格点：`data/8GJJ-C-Cip_charged.maps.fld`
- 运行环境：Ubuntu 24.04，conda环境 `dif`，Python 3.10，PyTorch 2.0.1+cu118，8× RTX 3080

### 3.5.2 代码架构现状

`ddpo/` 包已形成完整的分层架构，核心模块如下：

- **`integration/`**：DiffSBDD模型适配层，实现DiffSBDD与RLPF接口的双向兼容，处理 `batch_mask`（DiffSBDD flat格式）与 `node_mask`（RLPF padded格式）之间的互转
- **`trainer/`**：Lightning训练核心，`LightningDDPOModule` 实现 rollout → 语义标注 → 过滤 → 奖励 → PPO更新的完整epoch循环，并通过`dist.all_reduce`汇总全局指标
- **`rewards/`**：奖励函数系统，`BaseReward` 抽象基类 → `DruglikenessReward` / `DockingReward` → `CompositeReward`（加权求和）→ `StabilityAwareReward`（补充stability字段），由 `factory.build_rewarder()` 从配置一键组装
- **`runtime/`**：数据加载、分子采样（`DiffSBDDRollout`）、日志、种子管理
- **`utils/`**：分子语义标注（`annotate_batch_molecule_semantics`，计算SMILES/QED/SA/RDKit合法性）、多rank分子记录（`MoleculeRecorder`）、过滤器（`DiffSBDDFilter`，当前仅统计不删除）

### 3.5.3 已识别的技术问题

- **advantages未做基线减法**：当前实现中 `advantages = rewards`，缺少基线减法与归一化，可能导致优势函数方差偏大，影响PPO更新稳定性，已列入下一步改进计划。
- **recording子模块源码缺失**：`runtime/recording/` 目录仅存在字节码缓存，对应`.py`源文件已删除，功能已迁移至 `utils/molecule_recorder.py`，无功能影响但需清理遗留字节码。
- **`configure_optimizers`占位问题**：`LightningDDPOModule` 中Lightning优化器为占位SGD，实际参数更新由 `actor.update_policy()` 内部完成，`automatic_optimization=False`，两者职责已明确分离。
- **PyTorch版本兼容警告**：当前环境为 PyTorch 2.0.1+cu118，部分RLPF组件期望 PyTorch ≥ 2.2，已知不影响训练但需在环境升级时重新验证。

## 3.6 研究目标

### 3.6.1 总体目标

本项目旨在开发一套以RE-CmeB多药外排泵蛋白为研究对象的深度强化学习分子生成系统，通过构建多维奖励函数体系，利用RLPF框架对DiffSBDD扩散模型的分子生成策略进行系统性优化，最终筛选获得结构新颖、对接亲和力强、类药性优良、且与关键口袋残基形成合理相互作用的先导分子候选，为RE-CmeB靶向外排泵抑制剂的发现提供计算层面的原创支撑。

### 3.6.2 阶段性目标

**第一阶段（已完成）：强化学习闭环验证与类药性优化**

以druglikeness（QED + SA）为单一奖励组件，验证DDPO训练闭环的正确性与稳定性。
已达成指标：RDKit合法率峰值98.4%，平均QED达0.47，平均SA归一化值达0.59，训练过程稳定无崩溃。

**第二阶段（进行中）：引入对接奖励，实现多目标联合优化**

开启AutoDock-GPU对接奖励，与类药性奖励联合优化。目标指标：
- 生成分子对RE-CmeB的平均预测ΔG < −7.0 kcal/mol
- 有效分子对接成功率 ≥ 80%
- 类药性指标（QED > 0.4，SA归一化 > 0.5）在引入对接奖励后不显著退化

**第三阶段：引入PoseBusters与残基相互作用奖励**

结合前期分子动力学模拟所得RE-CmeB活性口袋残基重要性评分，通过ProLIF构建残基相互作用奖励。目标：
- 关键残基相互作用覆盖率（近端/远端口袋各≥2个关键残基）≥ 60%
- PoseBusters物理合理性通过率 ≥ 70%

**第四阶段：引入MolFormer流形判别器**

训练基于MolFormer嵌入+UMAP+KDTree的药物流形判别器，防止reward hacking。目标：
- 流形通过率 ≥ 80%（在已知药物分子集合上校验）
- 消融实验证明流形约束显著减少高分不合理分子比例

**第五阶段：候选分子筛选与计算验证**

从优化后模型中采样 ≥1000个分子，经全流水线过滤后，对Top候选进行精细对接、分子动力学验证与新颖性分析。
最终目标：获得 **3–5个** 结构新颖、ΔG < −5 kcal/mol、QED > 0.5、SA < 5、与关键口袋残基形成明确相互作用的RE-CmeB先导分子候选。

## 3.7 关键技术挑战与应对策略

**挑战一：无活性数据靶点的奖励设计**
RE-CmeB目前无已知抑制剂及活性数据，无法使用基于活性标签的奖励。应对策略：以对接自由能为结合亲和力代理，以残基相互作用评分（分子动力学来源）引导靶点特异性，以MolFormer流形约束保证化学合理性，形成多层次无标签奖励体系。

**挑战二：扩散模型与PPO的稳定性矛盾**
扩散模型生成分布对参数扰动极为敏感，过大更新步长会导致分布崩溃。应对策略：PPO裁剪参数ε设置在10⁻⁴量级、梯度裁剪（max_grad_norm=1.0）、极小学习率（10⁻⁵至10⁻⁶量级），以及后续引入KL散度约束项限制策略偏离程度。

**挑战三：多GPU对接的资源调度**
AutoDock-GPU的设备编号为1-indexed，与CUDA 0-indexed存在系统性偏移；对接为串行I/O密集型操作，在批量分子处理时易成为训练瓶颈。应对策略：代码层面显式换算（devnum = gpu_id + 1），对接任务按GPU分组批处理，临时文件使用进程级唯一路径避免冲突，失败分子显式记录不静默跳过。

**挑战四：分子重建语义一致性**
过滤、类药性计算与对接准备若各自独立重建分子，会引入语义分歧。应对策略：制定单一来源原则——OpenBabel重建→RDKit Mol→所有下游模块共享同一rdmol对象，禁止多路径并行重建。

### 3.5.3 已识别的技术问题

## 3.6 研究目标

### 3.6.1 总体目标

本项目旨在开发一套以RE-CmeB多药外排泵蛋白为研究对象的深度强化学习分子生成系统，通过构建多维奖励函数体系，利用RLPF框架对DiffSBDD扩散模型的分子生成策略进行系统性优化，最终筛选获得结构新颖、对接亲和力强、类药性优良、且与关键口袋残基形成合理相互作用的先导分子候选，为RE-CmeB靶向外排泵抑制剂的发现提供计算层面的原创支撑。

### 3.6.2 阶段性目标

第一阶段（已完成）：强化学习闭环验证与类药性优化

以druglikeness（QED + SA）为单一奖励组件，验证DDPO训练闭环的正确性与稳定性。
已达成指标：RDKit合法率峰值98.4%，平均QED达0.47，平均SA归一化值达0.59，训练过程稳定无崩溃。

第二阶段（进行中）：引入对接奖励，实现多目标联合优化

开启AutoDock-GPU对接奖励，与类药性奖励联合优化。目标指标：
- 生成分子对RE-CmeB的平均预测ΔG < -7.0 kcal/mol
- 有效分子对接成功率 >= 80%
- 类药性指标（QED > 0.4，SA归一化 > 0.5）在引入对接奖励后不显著退化

第三阶段：引入PoseBusters与残基相互作用奖励

结合前期分子动力学模拟所得RE-CmeB活性口袋残基重要性评分，通过ProLIF构建残基相互作用奖励。目标：
- 关键残基相互作用覆盖率（近端/远端口袋各>=2个关键残基）>= 60%
- PoseBusters物理合理性通过率 >= 70%

第四阶段：引入MolFormer流形判别器

训练基于MolFormer嵌入+UMAP+KDTree的药物流形判别器，防止reward hacking。目标：
- 流形通过率 >= 80%（在已知药物分子集合上校验）
- 消融实验证明流形约束显著减少高分不合理分子比例

第五阶段：候选分子筛选与计算验证

从优化后模型中采样 >= 1000个分子，经全流水线过滤后，对Top候选进行精细对接、分子动力学验证与新颖性分析。
最终目标：获得3-5个结构新颖、ΔG < -5 kcal/mol、QED > 0.5、SA < 5、与关键口袋残基形成明确相互作用的RE-CmeB先导分子候选。
