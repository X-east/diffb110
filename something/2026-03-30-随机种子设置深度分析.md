**日期**：2026-03-30  
**调查范围**：DiffSBDD-DDPO Lightning 训练中的随机种子设置机制

## 1. 当前随机种子设置方式

### 1.1 主入口（`main_diffsbdd_lightning.py`）

```python
def main():
    # Parse arguments
    args = parse_args()
    
    # Set random seed
    set_seed(args.seed)                          # ← 自定义函数
    pl.seed_everything(args.seed, workers=True) # ← Lightning 函数
```

**默认种子**：`args.seed = 42`（来自 `parse_args()` 的默认值）

### 1.2 `set_seed()` 实现（`ddpo/runtime/seed.py`）

```python
def set_seed(seed: int):
    """Set random seeds for reproducibility."""
    random.seed(seed)           # Python 标准库
    np.random.seed(seed)        # NumPy
    torch.manual_seed(seed)     # PyTorch CPU
    if torch.cuda.is_available():
        torch.cuda.manual_seed_all(seed)  # ← 所有 GPU 使用同一个种子
```

**关键点**：`torch.cuda.manual_seed_all(seed)` 为**所有 GPU 设置相同的种子**

### 1.3 Lightning 的种子设置

```python
pl.seed_everything(args.seed, workers=True)
```

这会调用 Lightning 内部的种子设置，包括：
- PyTorch 种子
- NumPy 种子
- Python random 种子
- CUDA 种子
- cuDNN 确定性模式

## 2. 两张显卡的随机种子是否不同？

### 答案：**否，两张显卡使用相同的随机种子**

#### 原因分析：

1. **`torch.cuda.manual_seed_all(seed)` 的行为**：
   - 这个函数为**所有可用的 GPU 设置相同的种子**
   - 不是为每个 GPU 设置不同的种子
   - 官方文档：*"Sets the random seed for the current GPU and all GPUs"*

2. **DDP（分布式数据并行）中的种子管理**：
   - Lightning 的 DDP 策略会在每个 rank（GPU）上独立调用 `seed_everything()`
   - 但由于 `torch.cuda.manual_seed_all()` 的全局性，所有 rank 最终使用相同的种子
   - 这是**有意设计**，用于确保可重复性

3. **验证方式**：
   ```python
   # 在 rank0 和 rank1 上分别运行
   import torch
   print(f"Rank {rank}: Initial random value = {torch.randn(1)}")
   # 输出会相同（如果种子相同）
   ```

## 3. DDP 中的随机性来源

即使两张显卡使用相同的初始种子，生成的分子仍然**不同**，原因是：

### 3.1 数据加载器的随机性

```python
# ddpo/runtime/data_loader.py
def generate_batch(self):
    nodesxsample = torch.randint(
        self.min_nodes,
        self.max_nodes + 1,
        (self.group_sample,),
        device=self.device,  # ← 在 GPU 上生成随机数
    )
```

**问题**：`torch.randint()` 在 GPU 上执行时，会使用 GPU 的随机数生成器状态，而不是 CPU 的状态。

### 3.2 模型采样中的随机性

```python
# DiffSBDD/equivariant_diffusion/conditional_model.py
# 采样过程中调用 torch.randn() 生成噪声
```

**关键**：在 DDP 中，每个 rank 的 GPU 随机数生成器状态是**独立的**，即使初始种子相同。

### 3.3 为什么会产生不同的分子？

在 DDP 训练中：

1. **Rank 0（GPU 0）**：
   - 初始种子 = 42
   - 生成 batch 1：`torch.randint()` → 随机数序列 A
   - 生成 batch 2：`torch.randint()` → 随机数序列 B
   - ...

2. **Rank 1（GPU 1）**：
   - 初始种子 = 42（相同）
   - 但 GPU 1 的随机数生成器状态**独立演进**
   - 生成 batch 1：`torch.randint()` → 随机数序列 C（可能与 A 不同）
   - 生成 batch 2：`torch.randint()` → 随机数序列 D（可能与 B 不同）

**原因**：CUDA 的随机数生成器（cuRAND）在每个 GPU 上维护独立的状态。

## 4. 当前配置的可重复性

### 4.1 同一 GPU 上的可重复性

✓ **可重复**：如果在同一 GPU 上运行两次训练，使用相同的种子，会生成相同的分子序列。

### 4.2 不同 GPU 上的可重复性

✗ **不可重复**：
- GPU 0 和 GPU 1 生成的分子序列**不同**
- 即使使用相同的初始种子
- 这是 CUDA 随机数生成器的特性

### 4.3 全局可重复性

✓ **可重复**（在 DDP 中）：
- 如果重新运行整个 DDP 训练（2 GPU），会生成相同的全局分子序列
- 因为每个 rank 的随机数生成器状态演进是确定的
- 但 rank 0 和 rank 1 的分子**不会互换**

## 5. 如何实现 GPU 间的一致性？

如果需要两张显卡生成**相同的分子**，需要修改代码：

### 方案 1：在 CPU 上生成随机数，然后分发到 GPU

```python
# 修改 data_loader.py
def generate_batch(self):
    # 在 CPU 上生成随机数
    nodesxsample = torch.randint(
        self.min_nodes,
        self.max_nodes + 1,
        (self.group_sample,),
        device='cpu',  # ← 改为 CPU
    ).to(self.device)  # 然后移到 GPU
```

**效果**：所有 GPU 会使用相同的随机数序列（来自 CPU 的随机数生成器）

### 方案 2：使用 Lightning 的 `seed_everything()` 在每个 epoch 重置

```python
# 在 on_train_epoch_start() 中
def on_train_epoch_start(self):
    pl.seed_everything(self.config.get("seed", 42) + self.current_epoch)
```

**效果**：每个 epoch 重置种子，但同一 epoch 内 GPU 间仍然不同

### 方案 3：使用 DDP 的 `DistributedSampler` 的 `set_epoch()`

```python
# 在 dataloader 中
sampler.set_epoch(epoch)
```

**效果**：确保不同 rank 在同一 epoch 使用不同但确定的数据顺序

## 6. 当前代码的影响

### 6.1 对训练的影响

- ✓ **可重复性**：同一配置、同一 GPU 数量的训练是可重复的
- ✓ **公平性**：两张显卡各自生成不同的分子，增加了样本多样性
- ✗ **一致性**：GPU 0 和 GPU 1 的分子不同，可能导致统计偏差

### 6.2 对分子保存的影响

从 `molecules_rank0.csv` 和 `molecules_rank1.csv` 中看到：
- Rank 0 和 Rank 1 生成的分子**确实不同**
- 这是预期行为（由 CUDA 随机数生成器的独立性导致）
- 全局汇总 `molecules.csv` 包含两个 rank 的所有分子

## 7. 建议

### 7.1 如果需要完全可重复性

在 `main_diffsbdd_lightning.py` 中添加：

```python
# 在 set_seed() 之后
os.environ['CUBLAS_WORKSPACE_CONFIG'] = ':16:8'  # 或 ':32:8'
torch.backends.cudnn.deterministic = True
torch.backends.cudnn.benchmark = False
```

**注意**：这会显著降低训练速度（10-30%）

### 7.2 如果需要 GPU 间一致性

修改 `data_loader.py`：

```python
def generate_batch(self):
    nodesxsample = torch.randint(
        self.min_nodes,
        self.max_nodes + 1,
        (self.group_sample,),
        device='cpu',  # 在 CPU 上生成
    ).to(self.device)
```

### 7.3 当前配置的建议

**保持现状**：
- 当前配置已经足够可重复（同一配置可重复）
- GPU 间的差异增加了样本多样性
- 这对 RL 训练是有益的（避免过度拟合）
