# GitHub上传与版本管理规范

更新日期：2026-10-13。适用于本项目主代码仓库，配合根目录`.gitignore`和`AGENTS.md`使用。

## 上传范围

| 内容 | 规则 |
|---|---|
| 自己维护的源码、测试、依赖声明 | 纳入Git；包括`ddpo/`、`DiffSBDD/`、`chembl_classifier/`中的项目代码 |
| 训练/生成/评测配置与启动脚本 | 纳入Git；正式配置集中放在`launch/`，按任务逐项选择 |
| 长期文档、README、项目规则 | 纳入Git；不上传带凭据的配置或环境导出 |
| `analysis/`中的分析程序 | 默认保留`.py`、`.sh`；不要用实验目录名称把源码一起忽略 |
| 新增正式结果汇总 | 放在`analysis/published/<任务>/`，只收录经审阅的小型MD、CSV、JSON和必要图表 |
| 原始SDF/PDB、轨迹、全量对接、训练记录、权重 | 留在运行/数据目录；Git记录来源、版本、校验值和获取方式 |
| 第三方仓库、论文PDF、ZIP、知识库原始导出 | 保留本地；上传来源/版本清单和必要的本地源码补丁 |
| 临时文件、缓存、自动生成配置、迁移前后备份 | 排除；已有跟踪的临时产物需单独取消跟踪，保留本地文件 |

`.gitignore`不会取消已经存在的Git跟踪。当前已有的正式小图或报告不在本次规则更新中批量删除；后续逐项审查，新增成果使用明确的发布区。

## 分析结果与工作记录

- 发布区报告必须写明输入来源、配置/代码版本、分子语义、固定尝试数、种子和统计口径；不能只放奖励曲线而缺少分母和独立评价。
- 报告中的图表和汇总数据使用相对链接，并随报告提交；避免链接到本地忽略的`OUT/`、`data/`或`work_records/`而让克隆后的报告断链。
- 发布区不是全量实验备份。日志、轨迹、SDF、权重和原始数据继续按本地运行规范保存，另行备份；记录其获取方式与SHA-256即可。
- `work_records/`保持本地任务记录策略。适合共享的稳定结论整理到`docs/`或发布区。Git忽略不代表可以删除这些本地证据。
- `analysis/`下新增的程序输入配置若需要进入Git，应放入`launch/`等正式配置目录，或明确放入发布区作为小型复现配置。运行时自动生成的配置不默认上传。

## 参考依赖

维护[来源与版本清单](reference_projects.tsv)和[获取说明](参考项目获取与复现.md)。固定Git commit，不把下载日期、文件修改时间或仅有论文年份当成代码版本。

参考源码、检查点和数据分别获取。若本地参考代码有修改，应保存针对固定commit的源码补丁和验证说明；仅记录上游commit不能完整复现修改后的目录。

## 分支与提交

- 按一个逻辑任务提交，消息格式为`YYMMDD-N 简单中文描述`；规则清理、源码变更和正式结果可分别提交。
- `main`作为稳定整合分支；实验分支使用明确的路线/实验名称。已有分支保留，未经任务授权不改名、不自动合并、不重写历史。
- 实验分支通过对应验证后才纳入稳定分支；上传时使用明确分支名，检查该分支的上游。无上游的新分支首次推送才设置`-u`。
- 提交和推送需要当前任务授权；完善规则、查看Git状态不等于授权上传。
- 暂存必须逐项选择；不默认使用`git add .`、`git add -A`或强制添加忽略目录。

## 上传前检查

```bash
git status --short
git branch --show-current
git diff --cached --name-status
git diff --cached --stat
git diff --cached
conda run -n dif python scripts/check_git_upload.py
```

检查脚本只读取暂存内容和当前工作树的忽略规则，不改变工作区或索引，不提交和推送。它拒绝匹配当前忽略规则的强行暂存文件，并排查禁止的产物/备份目录、模型/原始分子文件、常见凭据文件及密钥标记，默认单个文件限10MiB（项目约定，不是GitHub平台上限）；确有必要的正式小图可经审阅后用`--max-file-mib`调整。

暂存区删除条目允许通过检查：取消临时文件的跟踪不会删本地文件。检查不能替代完整的秘密审查、源码审阅或实验验证，路径/大小通过也不代表代码已测试。

推送前还要审阅未上传的既有提交。已有上游的分支可用`git log --oneline @{upstream}..HEAD`和`git diff --stat @{upstream}..HEAD`查看将发送的历史；没有上游时先明确目标远程分支及本地提交范围。仅检查暂存区或在最新提交中删除产物，不等于较早未推送提交中的产物已从历史移除。

代码提交另须遵守项目的语法、相关测试与GPU任务验证规则。未运行的测试、未完成的长任务必须明确记录，不能写成通过。
