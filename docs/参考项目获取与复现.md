# 参考项目获取与复现

更新日期：2026-10-13。

第三方源码位于`reference project/代码/`，该目录、论文、笔记和原始归档均不随主仓库上传。克隆主仓库后，应根据[reference_projects.tsv](reference_projects.tsv)恢复需要的项目。

## 清单字段与边界

清单记录项目名、相对目录、来源URL、当前Git commit、源码工作树变更数量（含权限变化）、未跟踪源码数量、README和环境配置位置。来源及commit从参考项目自身的Git元数据读取；不能把主仓库的Git信息误当成一个无Git元数据参考项目的版本。

有完整Git信息的行可用于获取固定上游版本；`needs_source_version`表示本地拷贝缺少可确认的来源或版本，使用它进行可分享的正式复现前必须补录。此快照不声称所有项目均已安装依赖、下载权重或通过运行验证。

## 恢复需要的源码

下面以DiffGui为例，仅适用于尚不存在的目标目录。不要在已有且有改动的本地参考项目上执行覆盖式恢复。

```bash
# 从清单复制DiffGui对应的source_url与commit_sha，替换占位符。
git clone --no-checkout '<source_url>' 'reference project/代码/DiffGui'
git -C 'reference project/代码/DiffGui' checkout --detach '<commit_sha>'
```

其他项目使用清单给出的`relative_path`，包括聚合目录内的子项目。主代码中的参考路径已经按`reference project/代码/`组织。

## 本地源码修改

先查看参考仓库的源码差异，确认没有把权重、数据、日志或凭据纳入补丁，再针对该项目的固定commit导出补丁。补丁和说明放在`docs/reference_patches/<项目>/`，写清修改目的、源commit和验证方法。

清单区分已跟踪源码改动和未跟踪源码。`git diff HEAD`不能自动收录未跟踪文件；新增源码须另行纳入补丁或明确的覆盖文件清单。不要把第三方目录整包复制进主仓库，也不要把本地修改误标成上游原版。

## 环境、权重与数据

- 主项目命令使用`dif`。DiffGui模型、采样和训练使用独立的`diffgui`环境，先运行依赖预检；不能把其他参考项目的所有依赖装入`dif`。
- 参考项目各自的README和环境配置是依赖安装的依据；清单只记录相对位置，不代表环境已验证。
- 模型检查点、数据集和配套工具按作者README分别获取，并记录下载来源、版本/配置与SHA-256。源码恢复不等于权重或数据恢复。
- 运行前核对实际项目目录、检查点路径和环境。不得用CPU加载成功推断GPU采样、训练或质量已通过验证。

## 更新清单

用`conda run -n dif python scripts/inventory_reference_projects.py`重新读取本地参考仓库元数据。默认只输出JSON到标准输出；指定`--output docs/reference_projects.tsv`才更新清单。该命令不克隆、不拉取、不checkout、不执行参考模型。
