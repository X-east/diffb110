# DiffB110 项目情况快速总览（Cursor任务前必读）

## 1. 项目一句话定位

这是一个**面向 RE-CmeB（8GJJ）靶点的分子生成与优化项目**：
以 `DiffSBDD` 作为 3D 分子扩散生成底座，用 `DDPO(PPO)` 做强化学习优化。

---

## 2. 项目目标规划（当前版本）

### 2.1 总目标
- 生成对目标蛋白口袋更友好的候选分子
- 在保证化学有效性的前提下，提升综合奖励（对接 + 类药性）
- 建立可复现实验流程（多 GPU、可记录、可追踪）

### 2.2 技术路线（当前已验证主线）
1. `DiffSBDD` 负责条件扩散采样（口袋约束下生成配体）
2. `ddpo` 将 DiffSBDD 包装进 RL 训练环
3. 奖励函数由 `CompositeReward` 组合：
   - `DockingReward`（当前 8GJL / 6卡流程使用 UniDock）
   - `ChEMBLPriorReward`（ChEMBL fingerprint 分布 prior，可替代或辅助 QED/SA）
   - `QEDReward` / `SAReward`（可选类药性组件）
4. 当前仓库内已验证、结构完整的训练主线是自定义单进程实现：
   - `ddpo/main_diffsbdd_single_gpu.py`
   - `ddpo/runtime/rollout.py`
   - `ddpo/integration/diffsbdd_model.py`
   - `RLPF-verl_diffusion/verl_diffusion/worker/actor/edm_actor.py`
5. 输出写入 `OUT/<run_name>_<日期>_<序号>/`，保存 config、epoch 指标、分子记录、checkpoint

### 2.3 当前里程碑状态（按仓库现状）
- 已有多轮训练输出与分析产物
- 当前 UniDock 链路已接入 8GJL / 6卡训练配置
- AutoDock-GPU 链路保留为历史验证和备选后端
- 当前仓库快照中，训练主入口应视为 `ddpo/main_diffsbdd_single_gpu.py`
- 文档中曾提及的 `ddpo/main_diffsbdd_lightning.py` 与 `ddpo/trainer/lightning_ddpo_module.py` 在当前树中不存在，应视为历史规划或其他工作树中的实现，不应再描述为本 checkout 的当前主线
- 仍保留大量历史脚本（`something/old-scripts/`），多数用于排查与旧流程回溯

## 9. Molecule 语义统一（必读）

当前项目关于 molecule 的统一方案已记录在：
- `docs/project_context.md`

核心决议如下：
1. OpenBabel 负责从扩散几何重建结构 / 感知建键
2. OpenBabel 判定不合理的样本即为不合理分子，直接最大惩罚并跳过后续所有阶段
3. 唯一主对象是转换后的 `rdmol`
4. `rdkit_valid` 作为 docking 前置门
5. `QED / SA` 只从 `rdmol` 直接计算
6. docking 输入只从同一个 `rdmol` 导出 `SDF/PDBQT`
7. `SMILES` 只用于日志、去重与 novelty
8. 最终总分必须是显式的分项加权组合
