# DiffB110 项目情况快速总览（Cursor 任务前必读）

> **最后更新**: 2026-06-04

## 1. 项目一句话定位

这是一个**面向 RE-CmeB / CmeB 口袋的 3D 分子生成、模型改造与强化学习优化项目**。

当前项目不再是单纯“DiffSBDD + docking/classifier RL”一条线，而是明确分成四条并行/候选主线：

1. **小改线**：继续使用 DiffSBDD 作为可运行底座，在模型内部加入 atom prior、geometry/bond length loss、bond-aware auxiliary head 等轻量改造，但暂时不把 bond/edge 作为扩散变量。
2. **大改线**：把 DiffSBDD 本体升级为可选 `DiffSBDD-xhe` 模式，在原有 protein-conditioned `x/h` 扩散链中加入 bond type / halfedge 的 `e` 扩散；standalone edge diffusion 只作为隔离验证工具，不作为最终替代底座。
3. **强化学习线**：保留并升级 DDPO/PPO 训练流程，未来重点修改 reward function，引入化学/几何护栏；高分好分子会进入 replay/top-N/self-training 数据池，用于后续重训练或偏好微调。
4. **DiffGui 强化学习线（候选第四线）**：将 DiffGui 作为更高质量但更慢的联合 `x/h/e` 生成底座，单独接入 DDPO/PPO；该线必须使用 `diffgui` 专用环境和 `ddpo/diffgui/` 解耦后端，不与现有 DiffSBDD RL 主入口混用。

## 2. 项目目标规划（当前版本）

### 2.1 总目标
- 生成对 RE-CmeB / CmeB 口袋有潜在结合能力、化学结构合理、可用于后续筛选的 3D 小分子。
- 在保留 DiffSBDD 快速生成优势的同时，系统性补齐其原子类型分布、几何、键长、成键和局部化学结构短板。
- 建立两套模型改造路线：短期可产出的小改路线，长期更彻底的 edge diffusion 路线。
- 建立可复现的强化学习优化流程：docking/classifier 不再单独主导 reward，而是和化学有效性、元素分布、环结构、碎片、几何稳定性共同约束。
- 将生成出的高分、合法、结构合理分子保留下来，作为后续 replay buffer、自训练、偏好微调或监督再训练数据。

### 2.2 四条主线

#### A. 小改线：DiffSBDD 内部轻量增强

目标：在不彻底改写扩散变量和采样链的前提下，尽快改善 DiffSBDD 生成质量。

重点模块：

- `atom composition prior / atom logits bias`：抑制全碳、杂原子不足、卤素位置异常等漂移。
- `x0 geometry / bond length loss`：让模型预测的最终坐标更接近合理键长和局部几何。
- `bond-aware auxiliary head`：从 t-conditioned hidden state 预测最终 bond existence/type，作为辅助监督或替代部分 OpenBabel 成键。
- `sampling-time geometry guidance`：在采样后段轻量修正过近/过远点云，降低明显几何异常。

定位：

- 这是六个月内最现实的论文/数据产出路线。
- 不要求一次性替换 DiffSBDD 全生成链。
- 与现有 DDPO/RL 主线兼容性最高。

#### B. 大改线：DiffSBDD-xhe 可选模式

目标：在不破坏原始 DiffSBDD `x/h` 生成和 DDPO/RL 主线的前提下，将 DiffSBDD 本体扩展为可选 `x/h/e` 扩散模型。

核心原则：

- 最终路线不是从零训练一个全新模型，而是在 DiffSBDD 内部加入 `e = bond/halfedge type` 扩散。
- `diffusion_mode=xh` 保持旧行为，继续服务现有普通 DiffSBDD 强化学习。
- `diffusion_mode=xhe` 才启用 halfedge 数据、edge transition、edge head、predicted-edge reconstruction。
- 新模式优先 warm-start 原始 DiffSBDD checkpoint，复用已有 pocket-conditioned 坐标/原子类型生成能力。

当前已建立的基础：

- `ligand_halfedge_index`
- `ligand_halfedge_type`
- oracle reconstruction
- edge semantic bundle
- edge transition smoke test
- standalone x/h/e 最小可训练 denoiser 骨架
- standalone edge DDP 训练和 sampler smoke

后续目标：

- 将已经验证过的 edge 数据链和 transition 迁移进 DiffSBDD 原始训练/采样链。
- 新增 DiffSBDD-xhe dynamics / edge head，使模型同时预测坐标、原子类型、边类型。
- 在 DiffSBDD loss 中加入 edge categorical loss 和 bond length 几何约束。
- 改造 `sample_given_pocket()`，使采样链同时更新 `x/h/e`。
- 用 predicted-edge reconstruction 替代或对照 OpenBabel 规则成键。
- 只有当 xhe supervised generation 稳定后，再设计 x/h/e joint logprob 并考虑接 DDPO/RL。

定位：

- 这是解决 DiffSBDD 成键和局部化学结构问题的更彻底路线。
- 开发风险高于小改线，因此必须以可选模式推进，不能破坏当前可运行 `x/h` 主线。
- 详细方案见 [DiffSBDD-xhe改造方案.md](DiffSBDD-xhe改造方案.md)。

#### C. 强化学习线：奖励函数升级 + 好分子回流训练

目标：让 RL 不再只追 docking/classifier，而是在优化结合倾向的同时守住化学合理性。

当前基础：

1. `DiffSBDD` 负责条件扩散采样（口袋约束下生成配体）
2. `ddpo/main_diffsbdd_ddp.py` 将 DiffSBDD 包装进 **PyTorch 原生 DDP** 训练环
3. 奖励函数由 `CompositeReward` 加权组合，当前支持 **14 种奖励组件**：
   - **对接类**：`DockingReward`（UniDock 后端）、`LigandEfficiencyReward`
   - **类药性**：`QEDReward`、`SAReward`
   - **ChEMBL 先验**：`ChEMBLPriorReward`（ECFP4/FCFP4 指纹相似度）
   - **高维特征分类器**：`ChemblClassifierReward`（2220 维 MLP，核心新增）
   - **人类偏好**：`MolSkillReward`（MolSkill 模型）
   - **分布匹配**：`LogPDistributionReward`（logP 分布对齐）
   - **多样性**：`DiversityReward`（ECFP4/FCFP4 批级多样性控制）
   - **化学有效性**：`ConnectivityReward`（连接性检查）
   - **化学/几何护栏**：`ChemistryGuardReward`（碳比例、杂原子、芳环、三元环、碎片、bad bond length、卤素异常等字段）
   - **归一化**：`ComponentNormalizer`（每分量 EMA z-score）、`RewardNormalizer`（全局 z-score）
4. 训练启动：`bash launch/<config>.sh`（torchrun 多 GPU DDP）
5. 输出写入 `OUT/<run_name>_<日期>_<序号>/`，保存 config、epoch 指标、分子记录、checkpoint

下一步 RL 重点：

- 加入三元环、碎片、异常价态、bad bond length、atom composition、芳香环分布等 guard reward。
- 对 docking/classifier reward 做更严格的归一化、clamp 和 failure penalty。
- 每轮保存 raw molecules、valid molecules、top-N rerank molecules。
- 好分子保留采用 `GoodMoleculePool` 方案：动态维护最近 10 轮中的高分且合理分子，而不是每轮孤立保存 top-N；append-only manifest 保留全部入池记录，`good_molecules_retained_rankXX.jsonl` 保存滑动窗口内的 retained top 分子。
- `GoodMoleculePool` 不能只按 docking/classifier 总分收分子，必须先经过 ChemistryGuardReward/结构护栏，或用 `quality_filters` 按字段限制三元环、碎片、bad bond length、碳比例、异常卤素等指标，避免把 reward 漏洞固化进后续训练。
- 好分子进入训练分阶段推进：第一阶段只开 pool 审计分子质量；第二阶段小比例开启短窗口 `trajectory_replay`，从磁盘读取完整 rollout trajectory 参与 PPO；第三阶段再把长期稳定的高质量分子用于 supervised fine-tuning / preference fine-tuning。
- `trajectory_replay` 只保存 CPU/磁盘侧的完整扩散轨迹，不保存在显存中；PPO 训练时再按 microbatch 流式搬到 GPU。初始 replay 比例建议从 0.1 开始，`max_age_epochs` 默认跟随 10 轮 retained window，必要时缩到 1-3 观察 ratio/KL 稳定性。
- 好分子回流训练必须保留 diversity/scaffold 分层和每 scaffold 占比上限，不能只取全局 top score，避免模式坍缩。

#### D. DiffGui 强化学习线：高质量联合扩散底座候选

目标：在不污染现有 DiffSBDD RL 主线的前提下，探索 DiffGui 作为高质量联合 `x/h/e` 扩散底座的 DDPO/PPO 优化路线。

核心原则：

- DiffGui RL 是第四条候选线，不替代当前可运行的 DiffSBDD RL 主线；
- 所有 DiffGui 生成、logprob、actor、rollout 测试必须在 `diffgui` 专用环境中运行；
- DiffGui RL 使用 `ddpo/diffgui/` 专用后端和未来 `ddpo/main_diffgui_ddp.py`，不在 `ddpo/main_diffsbdd_ddp.py` 中加入后端分支；
- 只共享模型无关的 reward、recording、normalization、molecule scoring 工具；
- 当前采样/训练步数统一按 100-step 轨迹推进：`model.diff.num_timesteps = 100`、`diffgui_rollout.num_timesteps = 100`、`DiffGuiActor.NumSteps = 100`；
- 当前显存推荐配置为 `precision=bf16`、`freeze.mode=last_n_blocks`、`freeze.train_last_n_blocks=1`；必要时再启用 `graph_micro_batch_size=1`。

当前已验证：

- DiffGui 500 分子在同一分类器下分布优于 DiffSBDD 5000 分子；
- reference DiffGui checkpoint 可在 `diffgui` 环境中加载；
- 100-step rollout 可记录 `[100, batch]` old logprob；
- DiffGuiActor 可对同一条 100-step trajectory 重算 current logprob 并执行 PPO smoke；
- `2 × 24 atoms / 100 steps / bf16 / freeze last 1 block` 已通过真实 GPU smoke；
- 100-step 24 原子重构质量仍差，下一步要优先做 100-step vs 500-step 与 `gui_strength` 扫描。

定位：

- 这是“高质量但慢”的候选强化学习路线；
- 论文或后续结果中可作为 DiffSBDD RL 的强基线/替代底座探索；
- 开发必须与 DiffSBDD/xhe/原 RL 三条线解耦，避免环境、日志、模型入口和 reward 记录混杂。

### 2.3 当前实验证据

近期 8GJL/C1101 六模型横评显示：

- DiffGui 质量和 docking 最强，但 500 steps 生成速度很慢，不适合作为当前 RL 高吞吐主底座。
- DePPA 与 DiffSBDD 同源且速度接近，但其质量更稳；它主要值得借鉴的是 RL 稳定化、valid filtering、top-N rerank 和后评估流程。
- DiffSBDD docking 并非完全不可用，但 sanitize、芳香组织、碎片和局部化学结构明显拖后腿。
- PMDM、DiffInt、DiffPharma 可作为 interaction/pharmacophore/physics guidance 参考，但不适合直接无脑替换底座。
- standalone edge diffusion 10k/6GPU/3epoch 已证明 bond denoising 可学到 `eval real-bond F1≈0.85`，reconstruct t100 sanitize 约 0.78；但 prior t100 sanitize 仍为 0，说明最终应迁移到 DiffSBDD-xhe 本体，而不是把 standalone 小模型当新底座。

### 2.4 关键基础设施
- **分子描述子监控系统**：`ddpo/utils/molecular_descriptors.py`（LogP/TPSA/HBA/HBD/碳比例/杂原子/芳环/MMD/指纹相似度等 22 个指标）
- **冒烟测试**：`launch/smoke.sh`（1 GPU / 1 epoch / batch=4，全链路 DDP 验证 + 自动清理）
- **ChEMBL 分类器管线**：`chembl_classifier/`（数据提取 → 训练 → 评估 → 集成到 reward）
- **配置驱动**：所有组件通过 `launch/*.yaml` → `factory.py` 从配置构建
- 当前 UniDock 链路已接入 8GJL 靶点，AutoDock-GPU 保留为备选后端

## 4. 关键模块职责（做任务时优先看这些）

### 4.1 训练入口
- `ddpo/main_diffsbdd_ddp.py`
  - **当前唯一主入口**，PyTorch 原生 DDP（`torchrun` 启动）
  - 负责：读配置、建模、建 reward/filter/rollout、执行 DDP 训练循环、checkpoint 与日志
  - 启动方式：`bash launch/run_6gpu_dock.sh` 等

- `ddpo/main_diffsbdd_single_gpu.py`
  - 单 GPU 入口，legacy，不再作为主要训练入口
  - 保留用于快速调试

- `ddpo/main_diffsbdd.py`
  - 旧 Ray 入口，legacy，保留用于历史对照

### 4.2 模型适配
- `ddpo/integration/diffsbdd_model.py`
  - 把 DiffSBDD 模型包装成 RL 可调用接口
  - 处理 pocket 读取、采样接口、mask/格式桥接
- `ddpo/integration/mask_utils.py`
  - `batch_mask <-> node_mask` 双向转换

### 4.3 奖励系统（核心重构区，新增 2026-05）

| 文件 | 职责 |
|------|------|
| `ddpo/rewards/factory.py` | `build_rewarder()` 从 YAML 构建完整 rewarder |
| `ddpo/rewards/composite.py` | `CompositeReward` 加权组合 + `ComponentNormalizer` 集成 |
| `ddpo/rewards/component_normalizer.py` | 每分量 EMA z-score 归一化 |
| `ddpo/rewards/normalization.py` | `RewardNormalizer` 全局优势 z-score |
| `ddpo/rewards/chembl_classifier_reward.py` | **ChEMBL 二分类器奖励**（2220D MLP，当前核心组件） |

| `ddpo/rewards/molskill_reward.py` | MolSkill 人类偏好模型 |
| `ddpo/rewards/ligand_efficiency_reward.py` | 配体效率（LE = dock_score / heavy_atoms） |

### 4.4 ChEMBL 分类器独立管线（`chembl_classifier/`）

独立于 RL 训练环的完整管线：
- **数据构建**：`data/extract_negatives.py`（属性规则提取异常分子）→ `data/build_dataset.py`（正负样本 + MolSkill featurizer → `dataset.pt`）
- **模型**：`model.py`（3 层 MLP：2220 → 512 → 128 → 1），输入 2048 Morgan FP + 172 RDKit 2D 描述子
- **训练**：`train.py`（BinaryCrossEntropy，batch=256，epochs=100）
- **评估**：`evaluate.py`（AUROC / 阈值分析）
- **集成**：训练好的 `.pt` 权重被 `ChemblClassifierReward` 加载，参与 RL 训练

### 4.5 分子描述子监控系统（2026-05-21 上线）

- `ddpo/utils/molecular_descriptors.py`：纯函数，不依赖训练基础设施
- 每 epoch 计算 22 个指标：LogP/TPSA/HBA/HBD/碳比例/杂原子/芳环/比例警报/MMD/指纹相似度
- 由 `ddpo/runtime/train_helpers.py` 上的 `compute_epoch_molecular_descriptors()` 触发
- 结果通过 `extra_metrics` 写入 `training_summary.csv`

### 4.6 训练执行模块
- `ddpo/runtime/rollout.py`：rollout 实现
- `ddpo/runtime/train_helpers.py`：训练循环编排 + 描述子计算
- `ddpo/runtime/recording/*`：记录输出（metrics_writer / molecule_writer / run_recorder）
- `ddpo/runtime/actor.py`：当前 policy update（从 RLPF actor 本地化）

### 4.7 记录与统计
- `ddpo/runtime/recording/molecule_writer.py`：分子级 CSV 记录 + epoch SDF 导出
- `ddpo/runtime/recording/metrics_writer.py`：`training_summary.csv`（含描述子 22 列）
- `ddpo/utils/diffsbdd_filter.py`：有效性过滤、SMILES 去重与可选新颖性惩罚

关注字段：
- `reward.weights` — 组件启用与权重
- `reward.per_component_normalization` — 每分量 EMA z-score（enabled: true/false）

- `model.checkpoint` — DiffSBDD 底座 checkpoint
- `pocket.pdb_path` — 蛋白口袋 PDB
- `train.epochs` / `train.batch_size_per_gpu`
