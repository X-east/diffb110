# docs 文档索引

> 最后更新：2026-10-13　维护规则：**新增 / 移动 / 归档任何文档都必须同步本表**。
> `docs/` 只放**长期有效**的文档；逐日过程记录放 `work_records/<YYMM>/<YYMMDD>/`。

## 分层阅读（重要：不要试图读完所有文档）

| 层 | 文档 | 怎么用 |
|---|---|---|
| **L0 必读（1 份，≤80 行）** | `管线总览.md` | 动手改代码前**完整读一遍**；它告诉你有哪些管线、当前状态、入口在哪 |
| **L1 按需速查** | `workflow_commands.md`（命令）、`project_context.md`（语义/reward，只查相关节）、本索引 | **不要通读**，带着具体问题查 |
| **L2 深挖（按需）** | `overview/*.md`（管线级总审计）、`论文/*.md` | 只在需要某条管线细节/证据时打开对应那一份 |
| **L3 过程记录** | `work_records/<YYMM>/<YYMMDD>/`（569+ 份） | 只在追溯“某天改了什么”时按日期查 |

原则：**L0 必须短且必读；L1 查；L2 挑；L3 溯。** 任何文档若被引用为“必读”，长度必须 ≤80 行。

## 建议阅读顺序

1. `管线总览.md` —— 有哪些管线、各是什么状态、从哪进入（**唯一总览入口**）
2. `project_context.md` —— 项目方向、分子语义、reward 体系（细节）
3. 需要具体管线细节时，进 `overview/`

## 目录结构

```
docs/
├── README.md                 ← 本索引
├── 管线总览.md                ← 唯一总览入口（管线状态表 + 结论速查）
├── project_context.md        ← 项目方向 / 分子语义 / reward 体系
├── workflow_commands.md      ← 训练 / 生成 / 分析 / 对接 命令速查
├── project_paths.md          ← 目录与路径约定（部分内容待更新）
├── overview/                 ← 管线级实验总审计（长期参考）
├── 论文/                      ← 论文骨架与证据索引
├── images/                   ← 文档引用图片
└── archive/                  ← 已过时 / 冗余（只归档，不删除）
```
