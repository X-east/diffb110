# 260609 每日简报

## 前提

DiffGui 被定位为第四条候选线：高质量联合 `x/h/e` 生成底座 + 独立 DDPO/PPO 后端。今天目标是让 DiffGui RL 工程闭环成立，同时保持和现有 DiffSBDD RL 主线解耦。

## 干了什么

- 设计 DiffGui 强化学习解耦接入方案，不把 DiffGui 分支硬塞进 `ddpo/main_diffsbdd_ddp.py`。
- 完成 100-step rollout 与同轨迹 PPO replay smoke，补充 BF16 和 graph microbatch。
- 深入排查 DiffGui timestep 改短后重构率异常的问题，并修复 checkpoint 加载时错误复用 1000-step `time_emb` buffer 的 bug。
- 跑通 DiffGui + docking reward + PPO replay 的 batch sweep。
- 实现并验证 DiffGui 单卡正式训练和 2 卡 DDP 入口。
- 修复 reward-only 子进程 CUDA 设备映射错误。

## 分析结果

1. DiffGui RL 工程链路已经从 rollout、reward-only docking、advantage、PPO 到 DDP 写日志全部跑通。
2. 100/200-step 路线可以继续用作 RL 快速采样前提，但必须跳过 checkpoint 中 timestep 派生 buffer。
3. 当前耗时主要在 DiffGui rollout 与 PPO replay，UniDock fast 在小 batch 下不是瓶颈。
4. DiffGui 线路已经可做正式小矩阵，但需要重点监控 KL、clipfrac、reconstruction ratio 和 docking success。
