## 干了什么

- 调研 REINVENT、SMILES-RL、RL-Diffusion、GCPN/gym-molecule、DePPA、DiffGui 原项目中 invalid / bad molecule 的训练处理方式。
- 判断 DiffGui 在线 PPO 中“删除非法并反复采样补齐 batch”是否适合作为主线。
- 基于 next6 第四组 `DG-NEXT-04 ring_last3_pathology_guard` 启动续训到 total 50 epoch。

## 结果与数据

### 非法分子处理调研

| 场景 | 常见做法 | 对 DiffGui 的结论 |
|---|---|---|
| 预训练/数据集构建 | RDKit、元素、原子数等规则清洗 | 合理，但不是在线 PPO 处理 |
| 评测/生成输出 | 可循环采样直到攒够有效分子 | 可用于最终输出，不等于训练策略 |
| RL 在线训练 | invalid 给 0/-1、validity bonus、合法动作约束、或跳过 PPO loss | 不建议默认重采样补满 |

本项目已有能力：

| 能力 | 状态 |
|---|---|
| 生成后写完整 molecule rows | 已有 |
| `DiffGuiTrainingFilter.select` | 已有 |
| 只让 train_indices 进入 PPO | 已有 |
| `select_graphs` 图级切片 | 已有 |
| accumulate-until-target | 尚未实现，应作为 ablation |

结论：先开 train-only filter，保留所有 rejected rows 和失败原因；不要直接把主线改成 rejection-sampled PPO。

## 分析结果

1. 对 invalid / bad molecule 的推荐策略是“训练参与过滤 + 原始统计保留”，不是直接补齐合法 batch。
2. accumulate-until-target 可能有价值，但会改变 PPO 采样分布，必须作为显式 ablation，并记录 generated/accepted/rejected 与 acceptance rate。
3. DG-NEXT-04 续训是真正的模型和 optimizer 续训，不是从 base checkpoint 重新启动。
4. 这次按用户要求先直接续训，没有启用 valid-only 训练过滤；过滤版本应后续单独比较。
