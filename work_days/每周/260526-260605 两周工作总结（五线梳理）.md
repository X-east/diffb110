## 一、强化学习线：Reward Hacking → Classifier → KL/护栏/Pool

**叙事主线：** RL 训练出现全碳漂移 → 尝试外部 reward 失败 → 自建 classifier → classifier 接入后信号稀疏 → 设计 KL + 护栏 + Pool 三件套破局。

### 1.1 训练坍塌复盘（260526）

**背景：** 当时 DDPO 训练的 reward 组合是 docking + ECFP4/FCFP4 prior（跑在 7 GPU 上）。训练跑了 62 epoch 后复盘，发现模型不是"没学到东西"——而是学会了向错误方向漂移。

**62 epoch RL 训练漂移：**

| 指标 | epoch 1 | epoch 62 | 方向 |
|------|--------:|---------:|------|
| carbon fraction | 0.651 | 0.879 | ↑ 全碳化 |
| hetero atoms | 7.6 | 2.9 | ↓ 杂原子消失 |
| N atoms | 1.2 | 0.0 | 非氧杂原子归零 |
| ring count | 2.6 | 5.0 | ↑ 复杂环/稠环增加 |
| LogP | 0.3 | 3.5 | ↑ 亲脂性升高 |
| TPSA | 103.8 | 49.8 | ↓ 极性表面积下降 |

**初步判断：** docking和ECFP4/FCFP4 prior 主导的 reward 会把模型推向高碳低极性或者复杂环方向，而 ECFP4/FCFP4 prior 的权重不足以拉回药物分布。接下来自然的问题是：能不能加一个"药物合理性"的 reward 分量？由此引出 MolSkill 测试。
![rl descriptor trends](../analysis/rl_high_carbon_sparse_reward_20260604/rl_descriptor_trends.png)
### 1.2 MolSkill 测试 → 自建 classifier（260526）

**MolSkill 是什么：** 一个基于大规模化学家评分数据训练的分子评分模型。它的训练数据来自药物化学家对分子的主观评分（合成难度、药物相似性、结构合理性等），模型学习化学家的打分偏好后，对任意输入分子输出一个连续分值。因此理论上它比简单的规则-based 指标（如 QED、Lipinski）更贴近"化学直觉"，可以直接作为 DDPO 的 drug-likeness reward。（23年NC）

**为什么选它测试：** 1.1 发现 docking + ECFP4/FCFP4 prior 挡不住漂移后，最直接的想法是"加一个药物合理性评分"。MolSkill 是现成的预训练模型，接入成本最低，不需要自己标注训练数据。如果它方向正确，就不需要自建 classifier。

**测试结果：** 方向完全相反。

| 测试分子 | MolSkill 分数 | 问题 |
|----------|-------------:|------|
| ChEMBL 均值 | +0.82 | 基准参照 |
| 生成分子均值 | +12.50 | 给漂移分子异常高分 |
| 全碳 C10/C16/C20 | +19.01 / +24.07 / +29.89 | 鼓励全碳链/环 |
| 全硫 S8 | +48.27 | 对异常元素完全失真 |

**结论：** 外部预训练打分器如果不针对生成器漏洞校准，方向会与"药物合理"完全背离（给全碳/全硫最高分）。因此必须自建 classifier，用生成分子的真实漏洞作为负样本。

### 1.3 自建 ChEMBL classifier v0 → v0.1（260526-260527）

**260526（v0）：** 用 100K ChEMBL 正样本 + 18K 规则负样本（简单规则：碳比例 >0.95、无杂原子等），训练 2220D MLP（2048 ECFP4 + 172 RDKit 描述子 → 512 → 128 → 1）。test acc 99.42%，但这只是说明"正负样本能分开"，v0 的负样本太粗糙。

**260527（v0.1）：** 把生成分子的实际漏洞变成显式可枚举负样本标签：

| 漏洞标签 | 数值 | 解释 |
|----------|-----:|------|
| OUT valid strict drug-like core | 0.280 | 仅 28% 严格药物样 |
| OUT 三元环比例 | 0.519 | 51.9% 含三元环 |
| OUT C≥0.90 | 17.5% | ChEMBL baseline 约 1.5% |
| OUT hetero≤1 | 10.8% | ChEMBL baseline 约 0.4% |
| OUT benzene-like ring | 4.97% | strict ChEMBL 82.26% |

基于这些漏洞构建 v0.1 训练集，同时升级正样本定义：strict ChEMBL pool，Murcko scaffold cap=10 控制多样性。

| 指标 | v0 (260526) | v0.1 (260527) |
|------|------------:|--------------:|
| 正样本 | 100K ChEMBL | 100K strict ChEMBL pool |
| 负样本 | 18K 规则 | 70K 多标签 hard negatives |
| 总量 | 118K | 170K |
| test acc | 0.9942 | 0.9945 |
| ROC-AUC | — | 0.9998 |
| high_reward_bad recall | — | 0.9886 |

![classifier probability hist](../analysis/classifier_test_260407_sdf_20260527/classifier_probability_hist.png)

**当时判断：** v0.1 的高 accuracy 说明 classifier 能分辨好分子和坏分子。但当时还不确定把它接入 DDPO reward 后实际效果如何——后续训练复盘会回答这个问题。

### 1.4 Classifier 接入 DDPO 后的问题（260528）

**问题链：** 260527 把 v0.1 classifier 作为独立 reward 分量接入 DDPO → 启动 7GPU dock+classifier 25 epoch 训练 → 期望两个 reward 分量同向优化，但因为奖励过于严苛，符合标准的太少，模型没有学到东西。

**Classifier reward 饱和：**

| 条件 | 比例 |
|------|-----:|
| reward > 0 | 7.5% |
| reward ≤ -0.5 | 89.5% |
| reward ≈ -1 | 83.7% |

**核心矛盾：** classifier 用过硬映射把大部分样本压到同一个惩罚值，docking 和 classifier 优化方向不一致（top docking 分子往往被 classifier 判差），PPO 没有稠密梯度。

**进一步诊断（260604）：** 复盘同期 RL run 的分子属性漂移，量化奖励稀疏程度：

| 指标 | 起点 | 末轮/最新 | 解释 |
|------|-----:|----------:|------|
| carbon_fraction | 0.6546 | 0.7937 | 持续高碳化 |
| hetero_atom_mean | 7.49 | 4.56 | 杂原子减少 |
| TPSA | 104.17 | 60.97 | 极性下降 |
| classifier 正分占比 | — | 9.71% | 有效奖励极稀疏 |
| docking≤-8 且 classifier>0 | — | 3.79% | 可学习好样本极少 |

结论：PPO 需要足够多的好分子作为正例信号，但当前底座生成的好分子极少，PPO 学不到有效梯度，在大量坏分子中随机游走后必然钻 reward 漏洞。因此需要 RL 侧的系统性解法（见 1.5）。

### 1.5 RL 线解法设计：三件套（260604）

解决思路分三个层面：

| 层面 | 方法 | 作用 |
|------|------|------|
| **防漂移** | KL 约束（analytic_current_ref） | 不让模型偏离预训练分布太远 |
| **补正例** | GoodMoleculePool（历史好分子回放） | 把罕见的好分子存起来复用，增加正例密度 |
| **兜底** | ChemistryGuardReward（化学门控） | 硬性阻止全碳/无芳香/三元环等明显坏结构 |

三个组件各自解耦，可独立 ablation。即使 xhe 大改线提升了底座，这三个组件仍然必要。

#### 1.5.1 防漂移：KL 约束修复（260604）

**问题：** 历史 KL 模式存在问题： 旧版 KL 计算方向是 KL(ref ‖ current)，不惩罚 current 发散到低概率区域

**新增两种 KL 模式：**

| 模式 | 含义 | 状态 |
|------|------|------|
| `analytic_ref_current` | KL(ref ‖ current) 旧版 | 保留兼容 |
| `analytic_current_ref` | KL(current ‖ ref) **推荐** | 新增，方向正确 |
| `pretrained_logprob_k3` | DePPA/Schulman K3 近似 | 可选对照 |

#### 1.5.2 兜底：ChemistryGuardReward（260604）

**问题：** 即使 KL 约束阻止了模型大范围漂移，PPO 仍可能在小范围内找到 reward loophole（如减少芳香环、增加三元环来降低复杂度，从而骗过某些 reward 分量）。

**门控指标：** 碳比例、杂原子数、三元环、芳香环、键长异常。任一维度超出阈值 → 强负奖励，不依赖 classifier。简洁、可解释、不增加训练开销。

#### 1.5.3 补正例：GoodMoleculePool 10 epoch 审计（260604）

**问题：** 好分子极稀缺（仅 3.79%），PPO 每次更新只看到当前 epoch 的分子，历史好样本直接丢弃。在每个 epoch 只有不到 4% 正例的情况下，PPO 在极度稀疏的梯度上随机游走。

**解决思路：** 参考 SMILES-RL 的 replay 和 REINVENT 的 prior-agent，在磁盘维护好分子池。每个 epoch 把通过化学门控且分数高于历史中位数的分子存入池，下个 epoch 的训练 batch 中混入池中分子，人工拉高正例密度。

**已做，但未加入训练**

## 二、参考模型与评估分析

**承上启下：** 第一部分已证明：reward hacking 无法通过"调 reward 权重"或"加 classifier"解决。docking 和 classifier 两个 reward 分量优化方向不一致，classifier 信号饱和。**问题根源不在 reward 设计，而在底座 DiffSBDD 缺少键/几何/结构先验。** 因此 260529 开始系统调研：别的扩散模型是怎么处理成键、几何和结构控制的？哪些模块可以拆出来借给 DiffSBDD？

### 2.1 参考项目深度调研（260529）

| 参考项目 | 可借鉴点 | 对 DiffB110 的意义 |
|----------|---------|--------------------|
| BInD | bond distance guidance、two-hop guidance、steric clash guidance | 几何约束前移到采样过程，减少终局 reward 稀疏性 |
| DiffGui | halfedge/bond diffusion、bond predictor、bond length loss | 解决 DiffSBDD 无显式键变量的问题 |
| SMILES-RL | TopHistory、BinCurrent、RND/diversity filter | 为 GoodMoleculePool / replay training 提供参考 |

### 2.6 DiffSBDD 的问题归纳

综合第一部分（RL 线）和第二部分的横评证据，DiffSBDD 的核心短板明确：**扩散变量只有 x+h，没有显式键变量，成键全靠 OpenBabel 从坐标推测**，导致 sanitize 低（0.666）、芳香缺失（0.412）、三元环多（0.154），RL 训练时还会被高碳分子钻 docking reward 的漏洞。因此需要两条内部修改线——先跑轻量后处理修补（不改架构），如果无效再做大改（x/h/e edge diffusion）。

## 三、内部修改线一：小改线（轻量修补）

### 3.1 策略：三种后处理修正

不改模型架构，只对采样后的点云施加修正，三种方法均移植自成熟参考项目：

| 方法 | 来源 | 做法 |
|------|------|------|
| **原子类型偏移** | DecompOpt | 用训练集元素分布做先验，对原子类型 logits 加减偏移，拉回真实比例 |
| **坐标精修** | BInD guidance | 能量梯度优化坐标，惩罚过近原子、坏键长、口袋碰撞，小步微调 |
| **局部限制** | Pocket2Mol | 构造局部连接图，禁止 F/Cl/Br/I 出现在多连接位置 |

## 四、内部修改线二：键扩散大改线（x/h/e Joint Diffusion）🔄 进行中

**为什么做：** 第三部分说明轻量修补不够。DiffSBDD 扩散变量只有 x+h 没有显式键，成键全靠 OpenBabel 推测。思路是给 DiffSBDD 加入显式键训练，参考 DiffGui 的 halfedge/bond diffusion。

**经历了两个阶段的迭代：**

**阶段一（warm-start + 交叉熵）：** 键预测头嵌入 DiffSBDD，从原始 checkpoint 热启动，用交叉熵分类训练键预测。全量 50 epoch 跑完（best epoch 37），训练指标尚可（F1 0.54），但生成的 480 分子仅 0.6% sanitize——大量价态超限错误。根因是**训练与采样不匹配**：训练用交叉熵学的是"从加噪坐标预测干净键型"，但采样用的是离散扩散的 `q(e_{t-1}|e_t, e_0_pred)` 后验公式——模型从未被训练做这个计算。且深度对比 DiffGui 发现键信号强度弱约 10 倍（键嵌入仅 32 维，用固定 `add` 而非可学习 `cat+Linear` 混合距离特征）。详见 [260606-03 深度对比](../work_records/26-6/260606/260606-03%20DiffGui与xhe键信息参与EGNN坐标去噪深度对比.md)。

**阶段二（scratch + 扩散 KL，进行中）：** 终局改动——把 DiffGui 的完整键扩散训练范式移植到 DiffSBDD-xhe。三个关键变更：

| | 阶段一（旧） | 阶段二（新） |
|------|------|------|
| 键损失函数 | 交叉熵分类（endpoint prediction） | **扩散 KL 散度**（学习 `q(e_{t-1}|e_t)`） |
| 键先验 | uniform | **absorb（吸收态）** |
| 噪声调度 | linear | **segment 双段** |
| 热启动 | 从 DiffSBDD checkpoint | **从零训练（scratch）** |

核心逻辑：扩散 KL loss 直接优化后验分布，训练与采样对齐，消除阶段一的 train-sample mismatch。从零训练，x/h 和键同步收敛。

## 核心结论汇总

### 问题诊断

| 发现 | 证据 |
|------|------|
| DiffSBDD 底座缺少键/几何先验 | 扩散变量只有 x+h，成键全靠 OpenBabel 推测 |
| RL reward hacking 不是权重调参问题 | 62 epoch 碳比例 0.65→0.88，芳香环几乎消失 |
| MolSkill 不可靠 | 给全碳/全硫异常高分 → 促使自建 ChEMBL classifier |
| DiffSBDD 有 docking 潜力 | median -9.774，仅次于 DiffGui -10.983 |

### 小改线

| 结论 | 证据 |

| 保留为可选后处理工具 | 不进入主路径，但 RL 场景下可重新评估 |

| 组件 | 状态 |
|------|:--:|
| KL analytic_current_ref | ✅ |

**设计逻辑：** 三个组件解决的是同一个问题的不同侧面——好分子太少，PPO 学不到。KL 防漂移（不让坏的变更多），Pool 补正例（让好的被复用），Guard 兜底（硬性过滤明显坏的）。权重调优（调整 docking/classifier/guard 三个 reward 分量的比例）决定 PPO 实际看到的梯度方向，需要和这三个组件一起 ablation。
